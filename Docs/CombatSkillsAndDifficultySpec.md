# 技・煽り・5段階難易度 仕様案

## 1. 文書の目的と位置づけ

### 目的
現在の1対1のタイミング戦闘に対する技・煽り・5段階難易度の実装可能なルールを定義する。実装後も、プレイテスト前の数値は初期調整値として扱う。

### 文書の優先順位
- [GameplaySpec.md](./GameplaySpec.md) は実装済み挙動と未検証事項を記録する。
- この文書の技・煽りの内容は実装に使った提案案であり、ユーザーの想定と異なっていたため承認済み仕様ではない。技・煽りを再実装する前に内容を再確認する。
- 5段階難易度と敵ギミックのうち実装継続する部分は、各プロフィールと現在のコードを基準にする。数値はプレイテスト前の初期調整値であり、確定バランスではない。
- 実装上の追加判断・未検証事項は「実装状況と差分」に記録する。

### 対象範囲
- プレイヤー技2種、煽り1種
- 既存の単一敵「道場主」プロファイルを難易度別に変える5段階設定
- 技・煽りと敵行動／既存カウンター・回復との相互作用
- 実装に必要なデータ、状態、テスト項目

Wave制、複数敵、技の習得ツリー、装備画面、恒久成長、セーブデータ、オンライン要素は含めない。

### 用語
| 用語 | 定義 |
|---|---|
| 指撃 | 現行のAttackコマンド。1回のタイミング判定で通常ダメージを与える |
| カウンター | 現行のCounterコマンド。攻撃予兆に合わせて入力し、被弾を反撃に変える基本行動 |
| 技 | 1戦闘中の使用回数が限られる、通常指撃と異なる効果を持つコマンド |
| 煽り | ダメージを与えず、敵の次行動を予測可能な攻撃へ誘導するコマンド |
| 予兆 | 敵の次の攻撃種類・タイミングをプレイヤーが判断できる視覚／音声表示 |
| 普通基準 | 現行の`EnemyProfileSO_Normal`を基礎とする設計値。最終バランスを意味しない |
| 初期調整値 | 実プレイテスト前の初回実装・調整用の提案値 |

## 2. 現状調査：事実、曖昧な実装、未決定事項

### 2.1 仕様策定時点のコード／アセット（実装前スナップショット）
以下は仕様策定時点の記録であり、現在の実装状況については2.4を参照する。
- ビルドシーンはTitleSceneとBattleScene。バトルはプレイヤー対敵の単戦闘で、HPが0になると勝敗を表示する。Wave進行の処理は確認できない。
- プレイヤーのアセット値はHP 1000、Strength 100、Defense 50、RefreshAmount 100、RefreshTime 2秒、MaxBreakCount 2、BreakTime 3秒、CounterStateDuration 0.5秒。
- 現行の敵プロフィールは`EnemyProfileSO_Normal` 1件。HP 3000、Strength 120、Defense 20、RefreshAmount 100、RefreshTime 2秒、MaxBreakCount 3、BreakTime 3秒、CounterStateDuration 0.5秒、IdleTime 3秒、ReactiveCounterChance 1.0、AttackStateDuration 0.5秒、AttackWeight 80、RefreshWeight 20。
- 通常攻撃のタイミング位置`x`は0から1。通常攻撃倍率は`0.5 + 2x`（0.5～2.5倍）。現在のランク表示境界はBad `<0.3`、Good `0.3以上`、Great `0.5以上`、Perfect `0.98以上`。
- 敵の攻撃イベントは`Random.value + Random.Range(0.3, 0.7)`の倍率を使うため、式上の範囲は0.3～1.7倍。通常攻撃も敵攻撃もQTE／ダメージ処理は`CombatCalculator`を経由する。
- 敵AIの現在の行動選択に入るのはAttackと、HPが最大未満の場合のRefresh。プロフィールの`CounterWeight`、`GoadWeight`、`SkillWeight`は存在するが、実際の選択ロジックでは使用されていない。
- 敵はプレイヤーがAttackに入った際、プロフィールのReactiveCounterChanceで反応カウンターを試みる。試行開始待ちは0～1秒、CounterStateDurationは現在0.5秒。
- プレイヤーのCounter状態中に敵の攻撃が命中すると、現行コードはプレイヤー側CounterSuccessを判定し、敵にStrengthの25%の反撃を与える。敵Counter状態中にプレイヤー攻撃が当たる場合も敵側CounterSuccessで同率の反撃を行う。
- BattleStateにはSkill、Goadが宣言されているが、これらの実行処理・完了遷移は実装されていない。EnemyStateControllerにはSkill/Goad caseがあるが空。Player側Skillはボタンを無効化するだけで完了処理がない。
- TitleSceneには非操作の`SkillCustam`オブジェクトがある。現行の技習得・装備UIとは確認できない。BattleSceneでは5個のコマンドボタン参照枠があるが、5個目が技かどうかはScene上のコード参照だけでは確定できない。
- TitleSceneには難易度選択ボタンの配置があるが、確認できた敵プロフィールアセットはNormal 1件である。5難易度すべてが正しく構成済みとは言えない。少なくともボタンPrefab単体のプロフィール参照は未設定で、Scene側Overrideで指定される構造。
- `StatusConst.Defense`は現在のCombatCalculatorダメージ式で使われていない。防御力を難易度差に利用するには、独立した仕様決定と実装変更が必要。

### 2.2 実装はあるが、正式ルールとして不明確な内容
- カウンターが成立する時間窓と入力タイミングの関係。プレイヤーCounter状態は0.5秒だが、敵攻撃アニメーションイベントとの境界動作はPlay Modeで未確認。
- 敵の通常攻撃倍率にランダム変動がある。現行コードでは予兆と攻撃強度の連動は確認できず、本提案では予兆開始時に倍率を確定して3段階表示する。
- EnemyProfileのRefreshWeightはHPが少しでも欠ければ選択対象になる。回復量は2秒で合計100だが、発動HP条件や使用回数制限はない。
- Break用カウントはプレイヤー／敵双方に実装されているが、名称と加算条件だけでは、プレイヤーが何を何回成功すると敵をBreakできるかがプレイヤー向け仕様として明瞭でない。
- DifficultyButtonは個々に`EenmyDifficultyListSO.Data`を保持するが、難易度ID、5段階の対応、プロフィールの完全な割当は確認できない。

### 2.3 仕様策定時点の未決定事項
技名・効果・使用回数、煽りの意味と敵応答は未承認の提案として扱う。実装された技と煽りは撤去済みで、次回実装前にユーザーの想定に合わせて設計を更新する必要がある。敵個体追加、ギミック説明画面、Victory/Defeat後の再戦導線、将来Waveを含めるかも未決定である。以下の数値はプレイテスト前の初期調整値である。

この節はコード・Scene・ScriptableObjectの実装結果を反映する。コンパイル成功はUnity Editor上の挙動確認を意味しない。

| 機能 | 実装状況 | 実装箇所／備考 |
|---|---|---|
| 5段階難易度 | 実装済み・コンパイル検証済み | `DifficultyId`と5プロフィールを作成し、TitleSceneの各ボタンに対応付け。ボタンと遷移時に未設定・ID不一致を拒否 |
| 技（旧案：震脚崩し／受けの構え） | 未実装（再設計待ち） | 実装コード、選択UI、使用回数、Guard軽減、QTE連携を撤去。旧案は未承認 |
| 煽り | 未実装（再設計待ち） | プレイヤー入力、敵応答予約、フェイント、ロックアウトを撤去。旧案は未承認 |
| 難しい以上のRefresh条件 | 実装済み・コンパイル検証済み | HP50%以下かつ欠損HPがRefreshAmount以上のときのみ、既存重みでRefresh候補に追加 |
| 敵Refresh中断時の回復量 | 実装済み・コンパイル検証済み | 中断分を実行時の残回復量から差し引き、完了前に中断して再選択しても同じRefreshAmountを繰り返し得ない |
| 達人以上の連続攻撃対策 | 実装済み・コンパイル検証済み | 同じ基本指撃を3回続けた後、次の攻撃系入力に即時ReactiveCounterを試行。Idle中または敵Attack予兆中なら成立。予告表示あり。非攻撃行動で解除 |
| 超越者の二段連携 | 実装済み・コンパイル検証済み | HP50%以下、基本指撃3連続履歴があり、プロフィール確率20%に成功した通常敵攻撃を2段化 |
| 難しいの予兆中反応Counter | 実装済み・コンパイル検証済み | 敵Attack予兆中にプレイヤーが攻撃系コマンドを選んだ場合、プロフィールのReactiveCounterChanceで判定。成立時は予兆中の敵攻撃を中断し、プロフィールの既存試行待ち後にCounterへ移行。難しいの初期確率は100%。 |
| Unity実行時検証 | 未検証 | Play Mode、Scene/Inspector参照、Animatorイベント、QTE操作、実戦バランスを手動確認する必要あり |

難易度・戦闘処理に関する実装判断:
- Animatorの敵攻撃クリップには`DecideDamageAmount`イベントが0.625秒位置にある。難易度プロフィールの`AttackStateDuration`を0.75秒にしてイベントを受ける猶予を確保し、イベントが欠落した場合だけ0.75秒で代替解決する。これは攻撃イベントの取りこぼしを避ける実装上の安全策で、手動確認は未実施。
- 敵Refreshは実行時に残り回復量を保持する。中断では回復予算をリセットせず、RefreshTimeの完了時にのみRefreshAmountへ戻す。プレイヤーRefreshのルールは変更していない。
- 二段連携は「HP50%以下」かつ基本指撃履歴3回以上を選択条件とする。
- 難しいの予兆中Counterは、ユーザー確認により「プレイヤーの攻撃系コマンドへの反応」として確定した。難しいプロフィールのReactiveCounterChanceとCounterAttemptDelayMin/Maxを再利用し、判定成立時だけ敵の攻撃予兆を中断してCounter試行へ移行する。プレイヤーが非攻撃行動を選んだ場合や確率判定に失敗した場合、敵攻撃は継続する。
- 技・煽りの実装は、ユーザーが現行案を想定と異なると指摘したため撤去した。ここに記載された技・煽り仕様は旧提案として残し、再実装の根拠として扱わない。

## 3. 推奨するゲーム全体ルール

### 3.1 戦闘の基本
1. TitleSceneで難易度を選び、BattleSceneに単体の道場主を読み込む。
2. プレイヤーはIdle中に「指撃」「カウンター」「休息」「技」「煽り」のいずれか1つを選ぶ。
3. 敵はプロフィールの待機時間後に、告知された行動を実行する。攻撃予兆中にカウンターが有効。
4. 技使用回数は1戦闘ごとに初期化。休息は現行どおりHPを回復するが、技回数は回復しない。
5. どちらかのHPが0以下になった最初の結果で戦闘を終了する。既存の終局ガードを維持する。

### 3.2 既存値を基準にする数式
- 通常の指撃ダメージ: `PlayerStrength × (0.5 + 2 × x)`。`x`は0～1にClamp。
- 通常の敵攻撃ダメージ: `EnemyStrength × AttackRoll`。初期仕様では既存乱数の範囲0.3～1.7を維持する。攻撃予兆を開始した時点で倍率を一度だけ確定し、予兆中に倍率帯（弱 `<0.75`、中 `0.75～<1.25`、強 `≥1.25`）を表示する。これにより、防御判断後にダメージが再抽選されない。倍率帯を表示できない実装では、攻撃倍率を1.0固定とする。
- カウンター成功ダメージ: `反撃側Strength × 0.25`。本仕様案では既存式を変更しない。
- HPは`0～MaxHP`。敵の防御値は現行で計算に未使用のため、難易度表では値を増減させず、将来使うなら別途仕様変更として扱う。

### 3.3 QTE公平性
初回実装では5難易度共通でQTE速度と既存ランク境界を維持する。難しさは敵の予兆、行動選択、ギミック対応で段階化し、反応速度だけを罰する難易度差を避ける。

| 判定 | xの範囲 | 通常攻撃倍率の範囲 |
|---|---:|---:|
| Bad | `0 ≤ x < 0.30` | `0.50～1.10` |
| Good | `0.30 ≤ x < 0.50` | `1.10～1.50` |
| Great | `0.50 ≤ x < 0.98` | `1.50～2.46` |
| Perfect | `0.98 ≤ x ≤ 1.00` | `2.46～2.50` |

境界は現行表示ロジック由来。プレイテスト前に判定幅を難易度別に変えない。

## 4. 技コマンド仕様（提案）

### 4.1 共通ルール
- 技は2種類。開始時に両方を使用可能とする。習得・装備画面は作らない。
- 2種類共通の技回数を戦闘開始時に2回付与する。種類ごとの上限は設けず、いずれかの技で消費する。残数0なら使用不可。
- 1回の使用で1回消費。成功・失敗・敵Counterによる反撃を問わず、発動開始後のキャンセルで返還しない。未発動（入力確定前）のキャンセルは消費しない。
- 休息、煽り、通常Counter成功では技回数を回復しない。無限ループを防ぐ。
- 技はプレイヤーIdle中のみ開始できる。終局後は使用できない。
- 震脚崩しを敵Attack予兆中に開始した場合、技のタイミング判定中に限り敵の残り予兆時間を停止する。Great/Perfectなら判定確定時に攻撃予約を直ちに中断し、Good/Badなら判定確定後に残り予兆時間を再開する。技QTEの入力上限は開始から2.0秒とし、未入力ならBad相当・0ダメージ・使用回数消費で予兆を再開する。敵Counter中は予兆を停止しない。
- 予兆なしに技を必須化しない。失敗時には技名と結果ランクを表示する。

### 4.2 技一覧

#### 技1：震脚崩し（攻撃中断）
| 項目 | 仕様案 |
|---|---|
| 役割 | ダメージ最大化ではなく、攻撃予兆を見て敵の攻撃を止めるテンポ技 |
| 使用条件 | プレイヤーIdle、技回数1以上。敵がAttack予兆中なら中断対象 |
| 使用タイミング | 使用開始で既存タイミングバーを1回表示。決定時点でランクを確定 |
| 予兆との時間処理 | 敵Attack予兆中は、震脚崩しのQTE開始から判定確定まで敵の残り予兆時間を停止。Great/Perfectの中断判定は入力決定時に適用し、Good/Badでは判定後に残り予兆を再開 |
| 対象 | 敵1体 |
| ダメージ | 通常攻撃式の`0.75倍`：`PlayerStrength × (0.5 + 2x) × 0.75` |
| Great/Perfect効果 | ランク確定時に敵が予兆中Attackなら、その攻撃1回を中断し敵を0.6秒間Staggerにする |
| Good/Bad効果 | 中断なし。0.75倍補正ダメージのみ。使用回数は消費 |
| 敵Counter相互作用 | 敵Counter状態中は通常どおり反撃を受け、攻撃中断効果は発生しない |
| 失敗 | 2.0秒以内に未入力ならBad相当・0ダメージ・使用回数消費。敵Attack予兆中なら停止していた残り予兆時間を再開 |
| 有効 | 敵の強攻撃予兆中。カウンター入力に自信がない場合や、回復動作より中断を優先したい場合 |
| 苦手 | 敵がCounter中、攻撃予兆がない時、技回数を使い切った時 |
| バランス調整値 | ダメージ係数0.75、Stagger 0.6秒、成功ランク下限Great |
| 狙うトレードオフ | 通常のPerfect指撃（最大2.5倍）より低いダメージと交換で、Great以上なら敵攻撃を1回止める |

#### 技2：受けの構え（被害軽減）
| 項目 | 仕様案 |
|---|---|
| 役割 | カウンターより入力猶予が広い代わりに、反撃ダメージを得ない防御技 |
| 使用条件 | プレイヤーIdle、技回数1以上 |
| 使用タイミング | 発動時に構えを開始し、2.0秒または次の敵攻撃命中まで有効 |
| 対象 | プレイヤー自身 |
| 効果 | 有効中に受ける最初の直接攻撃ダメージを50%軽減。残り時間と使用回数をUI表示 |
| 敵Counter相互作用 | 直接攻撃のみ軽減。敵のCounterSuccess反撃ダメージは軽減対象外とする |
| 敵Counter中 | 使用可能。敵がCounterSuccessを成立させた場合の反撃には軽減を適用しない |
| 重複 | 効果中の再使用不可。残り時間は延長しない |
| 効果消費 | 攻撃を軽減した時点で解除。敵の攻撃を受けず2.0秒経過した場合も解除 |
| 失敗 | 効果時間内に攻撃されなければ回数だけ消費して終了 |
| 有効 | カウンターのタイミングを読むのが難しい敵、敵行動の予測を外した場合 |
| 苦手 | 敵CounterSuccess、攻撃頻度が低い敵、被弾前に戦闘を終えられる状況 |
| バランス調整値 | 有効時間2.0秒、軽減率50%、1攻撃限定 |
| 狙うトレードオフ | Counterの反撃・Break圧力を捨て、失敗時の被害を確実に抑える |

### 4.3 技の濫用防止と敵の対抗
- 2回/戦の共有残数により、震脚崩しで敵攻撃をすべて止めることも、受けの構えを常時維持することもできない。
- 技を見て敵が無条件に無効化するルールは設けない。敵Counter状態、震脚崩しのランク、受けの構え時間という表示済み条件だけで相互作用を決める。
- 難易度が上がっても、Great境界、Stagger長、軽減率は変えない。高難易度では使用判断と残数管理を難しくする。

## 5. 煽りコマンド仕様（提案）

### 5.1 基本仕様「挑発」
| 項目 | 仕様案 |
|---|---|
| 役割 | 敵の待機・回復抽選を飛ばし、反応が予告された攻撃を誘ってCounter機会を作る |
| 使用条件 | プレイヤーIdle、敵Idle、前回挑発から敵行動を1回以上解決済み |
| 使用コスト | HP・技残数などのリソースは消費しない。プレイヤーの1行動を消費し、敵の次行動を誘発 |
| 効果 | 敵は次のAI抽選を1回だけ行わず、挑発応答攻撃を選択。敵は攻撃予兆終了後に攻撃 |
| 処理順 | 受理時に敵の通常待機時間を飛ばし、敵は既存Attack処理の予兆フェーズに入る。プレイヤーはGoad演出0.25秒後にIdleへ戻る。予兆中は通常どおりCounter／技／構えを選べる。技などで攻撃を中断した場合も応答予約を消費済みとして解除し、同じ挑発に対する再攻撃はしない |
| プレイヤー利益 | 予告された攻撃にCounterを合わせれば、既存式で反撃（敵Strengthの25%）。通常どおり攻撃を受ける危険は残る |
| 直接報酬 | 技残数、HP、ゲージを与えない。成功Counterの既存反撃のみ |
| 終了 | 挑発応答攻撃のダメージイベント実行、敵攻撃の中断、または終局で挑発応答フラグを解除 |
| 失敗 | Counterしない／失敗した場合、敵攻撃を通常どおり受ける。挑発自体の発動で敵攻撃予約は消費 |
| 連続使用 | 挑発応答攻撃が解決するまでは再使用不可。解決後も、通常の敵行動を1回完了するまでは再使用不可。中断された挑発応答も解決扱いとする |
| 非有効条件 | 敵がAttack、Counter、Refresh、Breakまたは終局中は選べない。選べない入力は発動せず、時間・リソースを消費しない |
| 休息との関係 | 敵のRefreshを中断しない。敵がRefresh中は挑発不能 |

### 5.2 敵の挑発反応
- 挑発応答は確率任せにしない。敵は難易度に応じて、予兆を表示した単発攻撃または予告付きフェイントを実行する。
- フェイントは攻撃を取り消す動作ではなく、初動の後も予兆表示を維持し、実攻撃時刻をUI／アニメーションで改めて明示する。
- 同一戦闘での挑発回数は記録する。2回目以降は反応パターンを難易度別に変えるが、隠れた攻撃や予兆なしの被弾は発生させない。
- 煽りでは敵を怒り状態にしない。敵のStrengthを恒久増加させる効果もない。

### 5.3 煽りの価値とリスク
- **価値:** 敵のAI待機・回復抽選を一時的に避け、次の攻撃をCounterで狙える。防御から反撃に移る計画を立てられる。
- **リスク:** 攻撃を避けられなければ被弾する。敵攻撃を止める効果はなく、技回数も増えない。
- **使わない判断:** HPが低い、受けの構えもCounterも使えない、挑発応答の予兆が苦手、敵が既に攻撃態勢の場合。
- **難易度差:** 高難易度は予兆の種類が増え、挑発反応の選択を読む必要がある。予兆そのものは常に表示する。

## 6. 5段階難易度（提案）

### 6.1 共通方針
- 同一の敵AIと行動セットを維持し、プロフィール値・予兆・挑発反応・条件付きギミック設定で差を作る。
- 難易度変更でPlayerDataSOや共有ScriptableObjectを書き換えない。EnemyProfileSO等の難易度別設定値を読む。戦闘中の残数・連続行動・状態は実行時データとして別に保持する。
- 普通の敵基礎値は現行`EnemyProfileSO_Normal`に揃える。他の難易度値はプレイテスト前の提案である。
- 敵HP／Strengthを同時に大幅増加させず、主に行動の読みと選択肢の管理で難しくする。
- QTE軌道、ランク閾値、Playerの基礎HP/Strength、技の2回共有残数、技効果、煽りの直接効果は全難易度で共通。

## 7. 敵ギミック定義

### G1：読みカウンター（普通を基準に全難易度）
- **目的:** 指撃を常時安全な選択にしない。
- **発動条件:** プレイヤーが攻撃系コマンドを開始し、敵がIdleの場合は全難易度でプロフィールのReactiveCounter判定を行う。難しいのみ、敵Attackの予兆中にも同じ判定を行う。
- **予兆:** 敵の手元に構えアイコン／固有音。予兆中はCounter状態またはCounter移行予定を識別できるようにする。
- **攻撃強度の公平性:** 通常攻撃倍率は攻撃予兆の開始時に一度だけ抽選し、倍率帯を「弱（`<0.75`）／中（`0.75～<1.25`）／強（`≥1.25`）」で予兆表示する。実装で強度表示ができない場合は、予兆後の通常攻撃倍率を1.0固定とする。ダメージ時に再抽選しない。この表示はCounterSuccessの固定ダメージには適用しない。
- **敵行動:** Idle中の反応Counterは既存の試行待ち後にCounter状態へ遷移する。難しいのAttack予兆中に反応判定が成立した場合は、敵の予約攻撃を中断して既存試行待ち後にCounter状態へ遷移する。プレイヤー攻撃がCounter中に解決すると敵CounterSuccessが反撃。
- **成功対処:** 震脚崩しのGreat以上は予兆中に敵攻撃を中断（Counter状態自体への技は無効）。敵攻撃にCounterを合わせれば既存反撃。
- **失敗対処:** 指撃を続ければ現行CounterSuccessリスクを負う。
- **難易度差:** 敵Counter確率・予兆猶予・Counter窓を難易度表の値にする。
- **実装要件:** 攻撃予兆状態と、敵Counter状態／QTE結果適用順の定義が必要。AnimationEventが遅れて届いても、中断済み攻撃ダメージを適用しない。

### G2：休息（現行機能の条件を明確化する提案）
- **目的:** 戦闘を長引かせる回復を、プレイヤーが識別・中断可能にする。
- **発動条件:** 敵HPが最大未満でAIがRefreshを選択。難しい以上はHP50%以下かつ欠損がRefreshAmount以上のときのみ候補。
- **予兆:** 回復開始時に「休息」表示。回復中の敵HPゲージ増加を表示。
- **成功対処:** 敵Refresh中に通常指撃または震脚崩しが命中すると回復をキャンセル。既存`CancelRefresh()`の挙動を維持。
- **失敗対処:** 中断しなければProfileのRefreshAmount/RefreshTimeまで回復し、最大HPを越えない。
- **煽り関係:** Refresh中は煽り不可。
- **難易度差:** 易しい／普通は現行どおり不足HPなら候補。難しい以上は発動条件を絞る代わりに、敵が回復を選んだことを明瞭に知らせる。
- **実装要件:** 回復量を実際の経過時間で加算し、HP0または終局後に回復を停止する。連続の部分回復で同じ回復量を何度も得る仕様にしない。

### G3：挑発応答（煽り専用）
- **目的:** プレイヤーの煽りに対し、リスクを伴う予測可能な攻撃を誘発する。
- **発動条件:** 敵Idle中に煽りが受理された場合、次の敵AI選択を一度置換。
- **予兆／敵行動:** 通常攻撃または難易度別のフェイント／連携を選び、攻撃前に予兆を表示。
- **成功対処:** Counter成功で通常のカウンター効果。受けの構えで一撃軽減。震脚崩しGreat以上は予兆中攻撃を中断。
- **失敗対処:** 攻撃が命中。直接的な煽り報酬はなし。
- **反復:** 挑発応答攻撃解決前は再使用不可。難しい以上では2回目以降、初動フェイントを0.35秒表示してから実攻撃予兆を示す。
- **実装要件:** `Goad`の入力受付・使用制限・応答予約・予約解除条件を定義し、予約攻撃のAnimationEvent二重実行を防止。

### G4：同じ手は読まれる（達人以上）
- **目的:** 1つの最適行動を連打する攻略を抑制し、複数の基本行動に意味を持たせる。
- **発動条件:** 指撃または同じ攻撃技を3回連続で使用した直後。
- **予兆:** 敵が構え直し、「同じ攻めを読んだ」専用表示。次の攻撃系コマンドにCounterすることを示すアイコンを表示。
- **敵行動:** 次の攻撃系コマンド入力時にCounterを必ず試みる。通常のReactiveCounterChanceとランダム試行待ちは適用しない。技攻撃も対象。敵がIdle中なら即時Counter、敵がAttack予兆中ならその攻撃を取り消してCounterへ移行する。構え・煽り・休息・Counterを選ぶと準備状態は解除される。
- **成功対処:** 準備状態を見て非攻撃系コマンドを選べばCounterを誘発せずに解除できる。攻撃技を使う場合は既知のCounterリスクを受け入れる。
- **失敗対処:** 攻撃系コマンドを続けるとCounterSuccessを受ける可能性が高い。
- **難易度差:** 達人は3連続後に一度適用。超越者では同じ履歴を連携攻撃の選択条件にも使う。
- **公平性:** 使用回数の隠れた罰、予兆なしの反撃、すでに確定した攻撃の後付け変更は禁止。

### G5：二段の連携（超越者のみ）
- **目的:** 一度のCounterだけでは解決しない敵行動を提示し、連続防御と残りリソースの管理を要求。
- **発動条件:** 敵HPが最大HPの50%以下で、同じ攻撃系コマンドが3回以上続いていること。次の通常敵攻撃候補に選ばれる確率は初期値20%。挑発応答攻撃としては選ばない。
- **予兆:** 連携アイコンと「1段／2段」を表示。各段の予兆時間は0.75秒。
- **敵行動:** 2回の独立した攻撃AnimationEvent。各段のダメージ倍率は通常攻撃式と同じ。1段目のダメージ後、2段目の予兆を0.35秒後に開始する。
- **成功対処:** 各段でCounterが有効。受けの構えは最初の1段だけ軽減。震脚崩しGreat以上はまだ攻撃されていない1段をキャンセルし、残りの連携を終了する。
- **失敗対処:** 防御に失敗した段ごとにダメージ。連続ヒットは最大2回。
- **例外:** プレイヤーまたは敵がHP0になった時点で残り段を取り消し、終局後ダメージは適用しない。
- **実装要件:** 連携IDと段番号を保持し、AnimationEventの重複・遅延、終局割込み、技による中断を冪等に処理する。高難度専用の多数の状態追加より、既存Attack状態＋連携データを推奨。

## 8. 代表的な戦闘例

### 8.1 通常の敵：普通の道場主
1. 敵は3秒待機し、HP満タンなら80:20重みからRefreshを除外した結果Attackを選択。
2. Attack前に1.1秒予兆。指撃を選び続けるか、Counterに切り替えるか判断する。
3. プレイヤーCounter中に攻撃が到達すれば既存25%Strength反撃。技は予兆攻撃を止める代わりに0.75倍ダメージ。
4. プレイヤーは2技回数と2秒ごとの敵Refresh機会を考慮し、HPを削る。

### 8.2 技対策が重要：難しい道場主
1. 敵が攻撃予兆を出したら指撃を続けるとReactiveCounterを受け得る。
2. Counterタイミングに自信がなければ震脚崩しを選択。Great以上なら攻撃1回を中断し、0.75倍ダメージで安全時間を得る。
3. 震脚崩しがBadなら中断できず、通常攻撃より低いダメージと使用回数を失う。次の予兆にはCounterまたは受けの構えを検討する。

### 8.3 煽りへの応答が重要：達人の道場主
1. プレイヤーは敵Idle中に挑発。敵は通常AI抽選でなく、挑発応答攻撃を予約する。
2. 予兆でCounter攻撃と確認できたらCounter。成功で既存25%Strength反撃。
3. 2回目の挑発にはフェイントが含まれるが、フェイント後に実攻撃予兆を表示する。読み違えても原因が表示から学習可能。
4. HPが低い時やCounterに失敗しやすい時は挑発しない。挑発は回復や技残数を与えない。

### 8.4 複合ギミック：超越者の道場主
1. プレイヤーが同じ指撃を3回連続すると、敵は「読み」予兆を出し、次の攻撃系コマンドをCounterする準備に入る。プレイヤーは非攻撃行動で解除するか、攻撃してCounterリスクを受け入れる。
2. HP50%以下で、連携攻撃を開始する可能性がある。1段・2段の予兆と番号を順に表示。
3. 受けの構えは最初の一撃にだけ使用されるため、2段目にはCounterが必要。震脚崩しをGreatで成功させれば未発生段を中断可能。
4. 予兆を見ずに攻撃を連打すると、連携で最大2段被弾する。敗因画面には「2段目の防御失敗」「同じ攻めを読まれた」等の原因を示す。

上記4例は同じ敵の難易度別行動例であり、現在複数の敵個体が実装済みという意味ではない。

## 9. 代表的なバランス比較

### 9.1 普通の敵への1アクション比較
PlayerStrength=100とすると、既存の指撃はBad時50～110、Good時110～150、Great時150～246、Perfect時246～250ダメージ。

| 行動 | 成功時の価値 | 失敗時／機会費用 |
|---|---|---|
| 指撃 Perfect | 約250ダメージ | 敵Counter中なら敵CounterSuccessの反撃を受ける可能性 |
| 震脚崩し Great以上 | 通常Greatの75%（約112.5～184.5）＋攻撃予兆を1回中断 | 2回の技回数の1回を消費。敵Counter中は反撃される |
| 受けの構え | 被ダメージを1回50%軽減 | 2秒間攻撃しない。敵攻撃が来なければ効果なし、回数消費 |
| Counter成功 | 25ダメージ（プレイヤーStrengthの25%）＋生存 | 窓を外すと通常攻撃を受ける。直接ダメージは低い |
| 煽り＋Counter成功 | Counter成功と同じ25ダメージ、敵行動を選択可能にする | Counter失敗で敵攻撃。技回数もゲージも得ない |

### 9.2 調整時の上限
- 技は合計2回/戦。技回数を回復する手段は初期仕様では存在しない。
- 受けの構えは1回の攻撃だけ軽減し、軽減率は50%を上限。
- 震脚崩しは攻撃1回を中断する。連携中は残り全段を中断してよいが、すでに適用済みダメージは戻さない。
- 挑発は敵の次の行動を1回だけ置換。通常AI行動の連続キャンセル不可。
- 連携攻撃の候補確率は0～1にClamp。
- 予兆の最低長は0.75秒。操作検証で不十分なら難易度個別ではなく全体を延長する。

## 10. 実装要件（コード変更なし）

### 10.1 必要な戦闘データ
難易度プロフィール（現行EnemyProfileSOまたはその入れ子データ）に以下を追加する案：
- DifficultyId（Easy/Normal/Hard/Master/Transcendent。表示文字列をIDに使わない）
- MaxHP / Strength / IdleTime / ReactiveCounterChance / CounterStateDuration / MaxBreakCount / BreakTime
- 攻撃予兆時間、Counter試行遅延Min/Max
- 技発動予兆への敵反応設定、挑発反応パターン
- Refresh HP条件、G4/G5の有効フラグと数値

設定値と実行中状態を分離する:
- 設定: ScriptableObjectの難易度／敵プロフィール（実行中に書き換えない）
- 実行時: 技残数2、受けの構え残時間、挑発応答予約、連続攻撃数、連携ID/段数、終局状態

### 10.2 コード連携点
- `TitleUIManager` / `DifficultyButton`: 5つの難易度IDとプロフィール参照の一意な割当。選択プロファイルがnullならBattleSceneへ遷移しない。
- `GameManager`: 戦闘開始時に難易度プロフィールと戦闘内技残数・連続行動データを初期化。
- `PlayerStateController`: Idle限定のSkill/Goad遷移と、演出終了／失敗後の必ずIdleへ戻る完了条件。終局後は既存ガードを維持。
- `EnemyStateController` / `EnemyDecisionController`: 予兆・行動予約・難易度パターンを一元的に進行。AI確率だけで予兆と攻撃を別々に抽選しない。
- `CombatCalculator` / Health: 技倍率・軽減を一度だけ適用。Counter反撃に防御技が誤適用されないようDamageKindを区別する。
- `TimingBarController`: 現行通常判定は維持。震脚崩しは同じQTE結果を用い、技ランク境界を別に複製しない。
- `GameUIManager`: 技残数、構え有効時間、煽り不可理由、敵予兆、連携段番号、敗因表示。
- AnimationEvent: 攻撃予約IDと有効状態を確認し、中断・終局後の遅延イベントを無視。重複イベントの二重ダメージを防ぐ。

### 10.3 例外・入力条件
- 技残数0、煽り不可中、プレイヤー非Idle、終局後の入力は拒否し、コストや状態を変更しない。敵Counter中の震脚崩しは入力可能だが、通常の敵CounterSuccess対象となり、中断効果は発生しない。受けの構えは敵Counter中も使用できるが、CounterSuccess反撃は軽減しない。
- 予兆攻撃が技で中断された場合は予約を1回だけ消去。EnemyDecisionControllerが直ちに同フレームで別行動を選ばない。
- Refresh中の攻撃割込みは既存CancelRefresh経路を利用。終局後は回復更新を停止。
- 強制シーン遷移時は技残数・予兆予約・連続回数を破棄。ScriptableObjectに実行状態を保存しない。
- nullまたは未設定プロフィールは既定プロフィールで無言に進めない。開発時に明確なエラーを出し、Player向けに難易度選択へ戻す動線は別途実装設計する（現行コードにはエラー表示・復帰処理がない）。

### 10.4 必須テスト
1. 5難易度ボタンがそれぞれ意図するDifficultyId/Profileを1つだけ選ぶ。
2. 普通プロフィールが現行基準値（HP3000、Strength120、Idle3秒など）と一致する。
3. 通常QTEのランク境界とDamage式が全難易度同じ。
4. 技共有残数が2から0まで減り、RefreshやCounterで回復しない。再戦で2に戻る。
5. 震脚崩しがGreat/Perfectかつ敵Attack予兆中だけ中断し、Good/Bad・Counter中は中断しない。
6. 震脚崩しのQTE中は敵Attack予兆の残り時間が停止し、Good/Bad後は残り時間から再開、Great/Perfectでは判定時に予約が解除される。2.0秒未入力で失敗・使用回数消費となる。
7. 敵通常攻撃の倍率は予兆時に一度だけ抽選し、表示した倍率帯と実ダメージが一致する。CounterSuccessに倍率帯表示は適用しない。
8. 受けの構えが次の直接攻撃1回のみ50%軽減し、CounterSuccess反撃には適用されない。
9. 煽りはEnemy Idle時だけ受理し、予約攻撃を1回実行。予約重複・未解除・連打が起きない。
10. 連続行動ギミックが同じ攻撃系コマンド3回で一度だけ発動し、Counter等の非攻撃系コマンドで解除。
11. 超越者の連携攻撃は最大2ヒット。各段Counter・構え・技中断を組み合わせ、二重イベントと終局後ダメージがない。
12. 難易度差がHP・Strengthだけでなく、予兆／行動条件／ギミックで現れ、予兆を欠かさない。
13. 結果画面後に技・煽り・Refresh・遅延AnimationEventが状態・HP・結果表示を変更しない。
14. Unity Editorで5段階を順に選択し、再戦・ホーム復帰・Consoleエラーを確認。

## 11. 既存仕様との互換性・代替案

| 判断 | 採用提案 | 採用しない案／理由 |
|---|---|---|
| 敵数／Wave | 1体の道場主を難易度別プロフィールで表現 | 新敵種やWaveは既存コードに基盤・要件が確認できず、範囲を増やすため保留 |
| 技取得 | 初期2技を全て使える固定構成 | TitleSceneの`SkillCustam`だけでは取得仕様の証拠がなく、装備UIや恒久成長は作らない |
| 技リソース | 2回/戦の共有残数 | 新しい極ゲージは現行データ・UIに存在せず、煽りでゲージを稼ぐ無限循環も防ぐ |
| 難易度差 | 普通値は既存Normalを維持し、行動・予兆中心に差をつける | Defenseを使ったダメージ式変更は既存CombatCalculatorとの仕様互換性がなく、別途承認が必要 |
| 高難度の公平性 | 行動の複雑さを上げるが全て予兆を出す | 隠し乱数、予兆なし攻撃、QTE速度だけの高難度化は採用しない |

## 12. 未決定事項・確認が必要な判断

| 未決定事項 | 推奨案 | 決定がない場合の影響 |
|---|---|---|
| 本仕様案を正式ルールとして採用するか | 数値は初期調整値として承認し、プレイテスト後に更新 | 実装者が技効果・難易度差を独自判断する |
| 5つの難易度表示名 | 易しい／普通／難しい／達人／超越者 | TitleScene表示・DifficultyIdの表示対応が決まらない |
| 技を2回/戦とするか | 初期プレイテスト用に2回。戦闘時間・勝率を見て調整 | 技の消費判断と受けの強さを数値化できない |
| 敵種は1体か複数か | まず1体の道場主の難易度差で完成させる | 別個体専用ギミックやAI分岐を今作るべきか決められない |
| 連続入力の計数対象 | 指撃または同じ攻撃技を3回連続で使用した場合に数える（提案。正式採用は未決定） | 達人以上の攻略に非攻撃系コマンドを使う意味を持たせる。数える技の範囲は実装開始前に確定が必要 |
| 初期調整値の妥当性 | 普通基準で勝率・戦闘時間を計測し再調整 | 難易度の実際の到達率・バランスは主張できない |
| 震脚崩しのQTEタイムアウト | 開始から2.0秒。未入力はBad相当・0ダメージ・回数消費 | 2秒は既存タイミングバーの約1往復に合わせた提案値。実機操作で短すぎる場合は、既存QTEと技の両方で一貫した時間を再調整する |
| 現行敵Counterの理不尽さ | 攻撃予兆を必ず明示し、Counter入力の有効時間をPlay Modeで検証 | 普通基準のReactiveCounterChance=1.0を維持すべきか判断できない |
| `Defense`の用途 | 今回は未使用のまま。利用するなら独立した仕様変更として承認 | Inspector上の数値から実際の被ダメージを推測できない |

## 13. 実装順序案（仕様承認後）
1. 5段階IDとプロフィール割当、普通の基準値を実データにする。
2. 既存攻撃／Counter／Refreshの予兆と完了条件をPlay Modeで確認する。
3. 技残数と受けの構えを追加し、DamageKind別の検証を行う。
4. 震脚崩しの中断と遅延AnimationEvent無効化を追加する。
5. 煽り応答予約と再使用条件を追加する。
6. 難しい以上の条件付きギミックを順次追加し、段階ごとにプレイテストする。
7. 勝率、平均戦闘時間、技使用率、煽り後Counter成功率、難易度離脱率で数値を再調整する。

仕様書作成時点でコード、Scene、Prefab、ScriptableObjectは変更していない。Unity Play Modeの動作確認、技の遊びやすさ、難易度バランスの実測は未実施。
